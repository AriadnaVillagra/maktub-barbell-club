# E0.4 — Job de Cloud Run con `mongodump` programado cada día

## Cambio

Agregar un script idempotente que crea un job de Cloud Run que hace `mongodump` y sube el dump al bucket, y lo programa para correr una vez por día.

## Dónde cae

- `scripts/`: script nuevo al lado de `desplegar-backend.sh` y `gcp-preparar.sh`, con el mismo estilo.
- Imagen del job: la elige el ejecutor; debe traer `mongodump` y poder subir a Cloud Storage. No va en `apps/backend/`.
- Programación del job: las fuentes piden "job programado de Cloud Run" (design.md §3.6); el mecanismo de disparo lo elige el ejecutor.
- Bucket y cuenta: los de E0.3.

## Debe ser cierto después

- Ejecutar el job a mano deja un dump en el bucket con nombre que incluye la fecha, y termina con éxito.
- El archivo no está vacío.
- El job está programado para correr una vez por día y la programación está habilitada.
- El script corre dos veces sin error y sin duplicar el job ni la programación.
- `MONGO_URL` sale del secreto `mongo-url`, no se escribe en el script ni en el repo.

## Restricciones

- CLAUDE.md › Commands (producción): `MONGO_URL` viene del secreto `mongo-url`; el usuario de Atlas cubre `mongodump`.
- CLAUDE.md › Hosting: backend sin APIs específicas de Google (el job vive fuera de `apps/backend/`); todo en free tier.
- design.md §3.5 y §3.6: `mongodump` a Cloud Storage con job de Cloud Run.

## Bloqueos externos

- `gcloud auth login` hecho por el usuario (CLAUDE.md › Commands).
