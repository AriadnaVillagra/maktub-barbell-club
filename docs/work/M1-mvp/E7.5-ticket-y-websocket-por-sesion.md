# E7.5 — Canal en vivo: ticket de un solo uso y WebSocket por sesión

## Cambio

Dos piezas de backend para abrir el canal de una sesión:

- Un endpoint HTTP que entrega un ticket de un solo uso y vida muy corta. Se pide con el token de
  acceso normal, en el header `Authorization`.
- Un WebSocket por sesión que acepta el ticket al abrirse. Si el ticket no es válido, rechaza la
  conexión.

No difunde eventos todavía. Eso es E7.6.

## Dónde cae

- `apps/backend/lib/features/sesion/` (slices de ticket y de conexión). El dispatch del WebSocket va
  en `routes/`.
- El lugar donde viven los tickets (memoria o Mongo) queda a definir en el issue. Con una sola
  instancia, la memoria alcanza (diseño, 9).

## Debe ser cierto después

- Un ticket sirve para una sola conexión: la segunda con el mismo ticket se rechaza (test).
- Un ticket vencido se rechaza. El valor de la vida es "muy corta" según el diseño; el número concreto
  lo fija el issue.
- Un ticket de otra sesión o de otro club se rechaza (test de aislamiento).
- El token de acceso nunca va en la URL (test o revisión de la ruta).
- `dart test` y `dart analyze` del backend quedan limpios.

## Restricciones

- Las APIs de WebSocket del navegador no mandan headers propios, y app y API están en sitios
  distintos, así que no hay cookies. El ticket es la forma de autenticar el canal (diseño, 9).
- Solo se abre el canal de una sesión existente, con el número de secuencia de E7.6 como siguiente paso.
- Código nuevo en inglés (CLAUDE.md).
