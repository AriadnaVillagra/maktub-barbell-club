# E0.3 — Bucket de Cloud Storage y cuenta de escritura para el backup

## Cambio

Crear el bucket de Cloud Storage donde van los dumps y la cuenta de servicio que puede escribir ahí, agregándolos al script de preparación de GCP en forma idempotente.

## Dónde cae

- `scripts/gcp-preparar.sh`: ya es el lugar de la preparación única e idempotente del proyecto (habilita APIs, crea cuentas y secretos). Se extiende con el bucket y los permisos.
- Cuenta `maktub-api` (ya creada por ese script): se usa solo como referencia; si el backup corre con otra cuenta, eso lo decide el ejecutor.
- No toca `apps/backend/`.

## Debe ser cierto después

- Correr `scripts/gcp-preparar.sh` dos veces seguidas no falla ni duplica nada.
- El bucket existe en el proyecto `maktub-514012`.
- La cuenta que escribe el backup puede escribir en ese bucket y no tiene otros permisos de proyecto.
- Ninguna credencial ni la `MONGO_URL` queda en el repo: sale del secreto `mongo-url`.

## Restricciones

- design.md §3.6 (Backup): un bucket de Cloud Storage y un job programado de Cloud Run. Nada de esto está en el repo hasta acá.
- design.md §3.5 (Scripts): el backup es `mongodump` (tarea 0.3).
- CLAUDE.md › Commands (producción): el usuario de Atlas `contacto_db_user` tiene el rol que cubre `mongodump`. No hace falta un rol de admin de Atlas.
- CLAUDE.md › Hosting: todo queda en el free tier.
