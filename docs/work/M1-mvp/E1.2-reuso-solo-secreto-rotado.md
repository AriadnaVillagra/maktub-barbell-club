# E1.2 — Reuso: solo cuenta un secreto ya rotado

## Cambio

Cambiar la renovación de sesión para que solo revoque la sesión del dispositivo cuando llega un refresh token que ya fue válido y se rotó; cualquier otro secreto erróneo se rechaza sin revocar nada.

## Dónde cae

- `apps/backend/lib/features/auth/refresh_session/refresh_session.dart`: hoy un secreto erróneo con id válido revoca la sesión.
- `apps/backend/lib/features/auth/refresh_session/refresh_session_store.dart`: `rotate()` guarda solo el hash nuevo. Para reconocer un secreto rotado, el store tiene que conservar los hash anteriores (o el último). El diseño concreto queda en el issue.
- `apps/backend/lib/features/auth/tokens.dart`: el id de sesión viene en el payload del access token. Cambiar el formato solo si hace falta.
- `apps/backend/test/features/auth/session_test.dart`: ampliar los tests de 1.2.

## Debe ser cierto después

- Un refresh con id de sesión válido y un secreto nunca emitido se rechaza, y la sesión del dispositivo sigue activa (test).
- Un refresh con un secreto ya rotado revoca la sesión de ese dispositivo (test).
- Un refresh con el secreto vigente sigue rotando como hoy (test).
- Otros dispositivos del mismo usuario no se tocan en ningún caso (test).

## Restricciones

- F1 §5 › Identidad: solo un secreto ya rotado cuenta como reuso. Rotación en cada uso y reuso que revoca la sesión del dispositivo son obligatorias.
- CLAUDE.md › Backend: vertical slices. El cambio queda dentro del slice `refresh_session`, y el store expone solo lo que ese slice usa.
- Código nuevo en inglés (CLAUDE.md, intro).
- Debe estar antes del merge de E1 (design.md §4.1, D2 y D5).

## Decisiones cerradas

- La regla de reuso (solo secreto rotado) ya está decidida en M1 (F1 §5, 2026-11-07).
- Esta corrección entra en M1 (design.md §2, D5).
