# E9.1 — Merge de `m1-mvp` a `main` y despliegue

## Cambio

Mergear `m1-mvp` a `main` (el último merge de M1) y desplegar las dos partes: la PWA en GitHub Pages desde `main` y el backend en Cloud Run con `scripts/desplegar-backend.sh`, con `ORIGENES_PERMITIDOS` apuntando al origen de Pages.

## Dónde cae

- Git: rama `m1-mvp` a `main`.
- Pages: el workflow que publica desde `main` (ver Bloqueos).
- Backend: `scripts/desplegar-backend.sh`, con `ORIGENES_PERMITIDOS=https://<usuario>.github.io` (CLAUDE.md, "Commands").

## Debe ser cierto después

- `main` tiene todo lo que quedó de M1 en `m1-mvp`, además de lo ya mergeado por épica.
- La PWA responde en `https://<usuario>.github.io` con el build de `main`.
- La API responde en `https://maktub-api-312703406459.europe-north1.run.app` con la versión nueva, y CORS acepta el origen de Pages.

## Restricciones

- No se agrega funcionalidad: solo sale lo que ya está en `m1-mvp`.
- Pages publica solo desde `main`.
- El backend sigue en una sola instancia (`max-instances=1`) y sin APIs específicas de Google en la imagen (CLAUDE.md).
- `MONGO_URL` y `TOKEN_SECRET` vienen de Secret Manager; no se pasan por el comando de deploy.

## Decisiones cerradas

- D2: cada épica se mergea al cerrarse. Este es el último merge y va antes de la prueba en el gimnasio (E9.3).

## Bloqueos externos
