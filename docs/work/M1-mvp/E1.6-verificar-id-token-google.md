# E1.6 — Verificar el ID token de Google en el backend

## Cambio

Agregar un verificador de ID tokens de Google que comprueba firma RS256 contra las claves públicas de Google, `aud` (client ID), `iss`, `exp` y `email_verified`, sin SDK de Google.

## Dónde cae

- `apps/backend/lib/features/auth/`: módulo nuevo junto a `tokens.dart`. Dónde exactamente lo decide el issue.
- Si hace falta una librería de JWT, va con versión exacta de al menos dos semanas (CLAUDE.md › Layout).

## Debe ser cierto después

- Acepta un token firmado con una clave pública de Google, con `aud` igual al client ID, `iss` de Google, no vencido y `email_verified` en true. Devuelve el `sub` y el email.
- Rechaza firma inválida, `aud` ajeno, `iss` ajeno, token vencido y email no verificado.
- Los tests usan claves y tokens de prueba y no llaman a Google.
- La prueba de punta a punta con el client ID real queda para E1.7 y E1.13.

## Restricciones

- F1 §5 › Identidad: verificación en el backend sin SDK de Google, con los cinco controles de arriba.
- CLAUDE.md › Hosting: el backend no usa APIs específicas de Google. Consultar las claves públicas por HTTP es lo único permitido.
- Código nuevo en inglés (CLAUDE.md, intro).

## Decisiones cerradas

- Verificación sin SDK de Google, con RS256 y los campos de arriba (F1 §5, M1 2026-11-07).

## Bloqueos externos

- El client ID real (E1.1) para la prueba de punta a punta. Los tests no lo necesitan.
