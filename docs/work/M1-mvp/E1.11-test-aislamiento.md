# E1.11 — Test de aislamiento reutilizable

## Cambio

Agregar un helper de test que, con una sola llamada, verifica sobre cualquier endpoint de club que sin membresía se rechaza, que sin el rol se rechaza, y que con otro `clubId` no se devuelven datos del club ajeno.

## Dónde cae

- `apps/backend/test/`: el helper, con los tests de ejemplo como guía de estilo (`test/features/auth/session_test.dart`, `test/infraestructura/http_test.dart`).
- Etapa 1 no tiene endpoints de club propios (el primero es E2.2). El helper se prueba entonces con un endpoint de prueba que tenga `clubId` en la ruta. Esto es una derivación, no algo que diga la épica.

## Debe ser cierto después

- Una sola llamada del helper aplica los tres casos a un endpoint.
- Sobre el endpoint de prueba, el helper pasa.
- Un endpoint de club que no filtre por `clubId` hace fallar el helper (verificado con un caso a propósito).
- La firma del helper queda pensada para que las épicas siguientes la usen sin copiar código.

## Restricciones

- Terminada cuando de E1: el test se aplica a cualquier endpoint con una sola llamada.
- F1 §5 › Contexto de cada pedido: rechazo sin membresía o sin rol, y filtro por `clubId`.
- design.md §3.3: test de aislamiento reutilizable.
- CLAUDE.md › Backend: los tests usan stores fake.
- Código nuevo en inglés (CLAUDE.md, intro).

## Decisiones cerradas

- Ninguna nueva. Se aplica la regla de E1.10.
