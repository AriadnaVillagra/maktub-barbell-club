# E5.3 — Backend: guardar un plan entero, atómico y validado

## Cambio

Agregar al slice `plan` el caso de uso `guardar`, que reemplaza el plan entero en una sola operación, lo valida en el servidor con las reglas de `maktub_core` y no deja nunca un plan a medias.

## Dónde cae

- `apps/backend/lib/features/plan/guardar/`: `guardar.dart` y `guardar_store.dart`, siguiendo el patrón de E5.2.
- `packages/maktub_core/lib/src/reglas/` y `modelos/`: validaciones y contratos de E5.1, que el servidor reusa.
- `reference/Api.gs`, función `guardarPlan`: ahí la referencia borra filas y después inserta, sin atomicidad. Solo apuntar, no copiar.

## Debe ser cierto después

- Guardar recibe el plan completo y lo reemplaza entero. Un plan con el mismo `id` del club se actualiza; no se crea un duplicado.
- Antes de escribir, el servidor corre la validación de E5.1. Si hay problemas, responde 4xx con la lista completa de problemas y no escribe nada.
- Un fallo a mitad de la escritura no deja el plan anterior ni uno parcial: el test con un store que falla en el paso intermedio deja el plan previo intacto.
- Guardar el mismo payload dos veces da el mismo resultado (idempotente).
- La auditoría del plan registra quién lo modificó y el instante en UTC.
- Solo el coach puede guardar. Un plan de otro club no se guarda y no cambia nada.
- El test de aislamiento de E1.11 corre sobre el endpoint y pasa.
- Tests con fake store y `dart analyze` limpio en `apps/backend`.
- El plan se guarda entero como un solo documento: esa escritura es atómica sin transacciones, que `mongo_dart` no tiene (design.md D15).
- La forma del error de validación (campos del JSON de respuesta) queda a definir en el issue.

## Restricciones

- design.md §3.3: slices de dominio como cortes verticales; test de aislamiento reutilizable (E1.11).
- CLAUDE.md › Backend: vertical slices: store propio con solo lo que usa; errores por el middleware, sin detalle en 500.
- CLAUDE.md › Backend: vertical slices: toda consulta y escritura filtra por `clubId`.
- CLAUDE.md › Backend: vertical slices: la infraestructura es solo Mongo genérico; el backend no usa APIs de Google.

## Decisiones cerradas

- Guardar es atómico: se guarda entero o no se guarda (epic E5).
- Las validaciones corren en el modelo (E5.1) y se repiten al guardar desde la app (E5.9). El servidor es la última barrera.
