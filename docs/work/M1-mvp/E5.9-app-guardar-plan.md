# E5.9 — App: guardar el plan con validación visible

## Cambio

Conectar el editor con el endpoint de guardar de E5.3: antes de enviar se corre la validación de `maktub_core` y se muestra por qué un plan no se guarda; después de guardar, el plan queda con su id y su auditoría.

## Dónde cae

- `apps/frontend/lib/features/plan/data/`: llamada de guardar en el repositorio, sobre `apps/frontend/lib/core/red/cliente_api.dart` (`ErrorDeApi` lleva el `{error}` del backend).
- `apps/frontend/lib/features/plan/presentation/`: acción de guardar y lista de problemas en pantalla.
- Validación compartida: `packages/maktub_core/lib/src/reglas/` (E5.1).
- `packages/maktub_ui/`: componente de lista de errores o aviso, si falta, con galería.

## Debe ser cierto después

- Guardar corre la misma validación de `maktub_core` que el servidor usa. Si hay problemas, no se envía nada y se muestra la lista completa, con día, bloque, prescripción y serie donde está cada uno.
- Si el servidor rechaza el plan, la app muestra su lista de problemas, sin inventar otra.
- Un error de red o de permiso se muestra como error, no como guardado.
- Después de guardar bien, el plan muestra su id y no se pierde al recargar la pantalla de lista.
- Con esta app, el coach reescribe a mano el plan de octubre 2026 (datos de la planilla, con el 80 % corregido) y lo guarda. Se verifica en la app; no depende de la importación de E8. Requiere ejercicios y temporizadores en el catálogo (E2).
- Tests de widget: plan inválido no llama al repositorio y muestra problemas; plan válido llama y muestra el id; `flutter analyze` limpio.

## Restricciones

- CLAUDE.md › Frontend: clean architecture per feature; Riverpod sin codegen; DI en `presentation/providers.dart`.
- CLAUDE.md › maktub_core: la validación es la de `maktub_core`, no una copia en la app.
- CLAUDE.md › maktub_ui: sin literales en la pantalla; componentes del paquete.
- CLAUDE.md › Frontend: `ErrorDeApi` del cliente HTTP para errores del backend.
- design.md §3.4: pantalla de editor de plan.
- diseno.md, Modo planificación (3, editor de plan) y (4, análisis del plan): el análisis queda fuera de M1.

## Decisiones cerradas

- Las validaciones se repiten al guardar desde la app, además de correr en el modelo y en el servidor (epic E5).
- Un plan inválido no se guarda y la app muestra por qué (epic E5).
