# E2.7 — Script idempotente de la semilla

## Cambio

Agregar el script que carga en `plataforma` la lista aprobada de E2.6 (ejercicios, categorías, temporizadores, WoDs, grupos musculares y patrones base), de forma que correrlo dos veces no duplique nada.

## Dónde cae

- Script de semilla: design §3.5 lo ubica entre los scripts; la carpeta exacta no está decidida (ver informe).
- Reusa `apps/backend/lib/infraestructura/` (conexión Mongo, `Colecciones`, `asegurarIndices`) y los modelos de `maktub_core` (E2.1 y E2.2).

## Debe ser cierto después

- Correr el script dos veces deja la misma cantidad de documentos que correrlo una vez.
- Solo carga el contenido de la lista aprobada en E2.6, sin agregar nada más.
- Todos los documentos cargados tienen `clubId` `plataforma` y pasan las validaciones de E2.1 y E2.2.
- Cada ejercicio base tiene músculos y patrón, y esos valores apuntan a grupos y patrones cargados (F2 criterio 10).
- Hay tests con un store falso: primera corrida, segunda corrida sin duplicados, y rechazo de un documento inválido.

## Restricciones

- design §3.5: la semilla es un script con una lista que el usuario aprueba antes de cargarla.
- CLAUDE.md › Backend: la infraestructura queda libre de APIs específicas de Google, para poder mover la imagen a otra VM.
- M1-D5: un base corregido se refleja en todos los clubes. Por eso el base vive en `plataforma`, no se copia por club.

## Decisiones cerradas

- La semilla es idempotente y carga solo la lista aprobada (M1 §5, tarea 2.4).
- Grupos musculares y patrones base se cargan en la semilla (design.md D10).
