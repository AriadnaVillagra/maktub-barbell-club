# E2.3 — Lectura del catálogo visible

## Cambio

Agregar los endpoints de lectura de ejercicios, categorías, temporizadores, grupos musculares y patrones visibles para un club (`plataforma` más el club actual), con filtro por categoría en ejercicios.

## Dónde cae

- `apps/backend/lib/features/catalogo/<slice>/`: un slice de lectura con `<slice>.dart` (endpoint y caso de uso) y `<slice>_store.dart` (interfaz y su implementación Mongo). Seguir el patrón de `apps/backend/lib/features/auth/`.
- `apps/backend/lib/routes/`: solo despacha el método HTTP.
- `apps/backend/lib/infraestructura/`: `Colecciones`, mapeo `_id`↔`id`, errores (`ErrorDeSolicitud`).
- Contexto de club y test de aislamiento: los entrega E1.

## Debe ser cierto después

- La lectura devuelve documentos con `clubId` `plataforma` o con el club actual. Ningún documento de otro club aparece.
- El filtro por categoría devuelve solo los ejercicios que tienen esa categoría.
- Cada documento trae su estado (`activo` o `archivado`). El criterio por defecto para archivados queda abierto (ver informe).
- Grupos y patrones se leen con el mismo criterio de visibilidad. Son la lista que usa el formulario de ejercicio (E2.8).
- El test de aislamiento reutilizable de E1 corre sobre el endpoint.
- Con la semilla cargada (E2.7), un club sin nada propio recibe el catálogo base completo (F2 criterio 1).
- Hay tests del caso de uso con store falso.

## Restricciones

- CLAUDE.md › Backend: vertical slices. Los slices no comparten repositorios; los tests usan stores falsos.
- CLAUDE.md › Backend: toda consulta filtra por `clubId`, con la regla de lectura plataforma + club (design §3.3; F2 §4).
- design §3.3: el club activo viene de la ruta `/clubes/{clubId}/…` (M1-D7 en design §2).
- CLAUDE.md › Backend: errores como `{error}` 4xx; cualquier otro error da 500 sin detalle.

## Decisiones cerradas

- Se leen base y del club juntos, con `clubId ∈ {plataforma, club}` (F2 §4).
