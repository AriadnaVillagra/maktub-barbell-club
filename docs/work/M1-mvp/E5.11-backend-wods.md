# E5.11 — Backend: biblioteca de WoDs del club

## Cambio

Agregar los endpoints para listar, crear, editar y borrar los WoDs de la biblioteca del club.

## Dónde cae

- `apps/backend/lib/features/wods/<slice>/`, un slice por caso de uso (CLAUDE.md, "Backend: vertical slices").
- `apps/backend/routes/clubes/[clubId]/wods/`: solo despacho por método.
- `apps/backend/lib/infraestructura/mongo.dart`: `Colecciones` y `asegurarIndices`.

## Debe ser cierto después

- El coach (`Accion.planificar`) lista, crea, edita y borra WoDs de su club. El listado va ordenado por nombre.
- Un atleta o un usuario sin rol de coach recibe 403.
- Un WoD de otro club no se ve ni se toca (`testClubIsolation`).
- Un WoD sin nombre o con una prescripción sin ejercicio se rechaza con 4xx y `{error}`, sin escribir nada.
- Tests con stores falsos; `dart analyze`, `dart test` y `dart_frog build` pasan en `apps/backend`.

## Restricciones

- El servidor fija `id`, `clubId` y la auditoría; lo que venga en el cuerpo se ignora.

## Decisiones cerradas

- Un WoD se puede borrar aunque se haya usado, porque los planes guardan una copia. No hace falta archivarlo.
