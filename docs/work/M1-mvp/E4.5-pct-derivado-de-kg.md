# E4.5 — % derivado de kilos escritos a mano

## Cambio

El porcentaje a registrar sale del peso tipeado dividido por el mismo denominador que usa el objetivo (RM × factor), de modo que volver a calcular el kilo con ese % devuelva el peso tipeado, o el cargable más cercano si no es cargable.

## Dónde cae

- `packages/maktub_core/lib/src/reglas/porcentajes.dart`: `pctDesdePeso(pesoKg, rm)` hoy no tiene factor y redondea a centésimas. `pesoPorPorcentaje` ya da el cargable más cercano.
- `packages/maktub_core/test/reglas_test.dart`, grupo `porcentajes`: el test "pctDesdePeso mantiene el invariante" tiene que seguir valiendo con factor 100 %.
- Referencia: `reference/Index.html`, `pctRegistrado`. Si la serie está tocada y hay peso, el % sale de peso / RM.
- El registro que guarda el factor es de E3 y E7, no de esta issue.

## Debe ser cierto después

- Con factor 100 %, el resultado es igual al de `pctDesdePeso` de hoy.
- Con otro factor, `pesoPorPorcentaje` con el % derivado devuelve el peso tipeado si es cargable, y el cargable más cercano si no.
- Sin RM (nulo o cero), no se deriva % y no hay error.
- Hay tests para: peso cargable exacto, peso no cargable, y factor distinto de 100 %.

## Restricciones

- Código nuevo en inglés (`CLAUDE.md`, "new code is written in English").
- Regla pura en `maktub_core`, con tests (`CLAUDE.md`, "Architecture › maktub_core").
- `dart test` y `dart analyze` limpios en `maktub_core`.

## Decisiones cerradas

- Cuando el atleta escribe el kilo, el % registrado sale del peso, para que `rm × pct ≈ peso` siga valiendo en el historial (`reference/DISENO.md`, "Invariante"; M1 §3, "Registro… igual").
- El criterio de E4 ("volver a calcular el kilo con ese % devuelve el peso tipeado") exige que el denominador sea el del objetivo. Con factor, eso lleva a dividir por RM × factor (ver E4, "Terminada cuando").
