# E0.2 — Service worker propio que guarda el shell de la app

## Cambio

Agregar un service worker propio que guarde los archivos de la app, registrarlo desde la página y dejar de depender del `flutter_service_worker.js` que genera Flutter.

## Dónde cae

- `apps/frontend/web/`: archivo nuevo del service worker (copiado tal cual al build) y `index.html`, donde se registra. El `<base href>` lo reemplaza `--base-href` en el build.
- `.github/workflows/pages.yml`: el build de Pages usa `--base-href "/<repo>/"` y `--no-web-resources-cdn`. CanvasKit tiene que quedar dentro del sitio para poder guardarse.
- `flutter_service_worker.js` generado en `build/web`: el stub que se desregistra solo (design.md §3.4).

## Debe ser cierto después

- Tras una primera carga con red, con la red apagada una recarga abre la app desde caché (se prueba en Chrome con DevTools en modo sin conexión).
- El service worker queda registrado con scope `/maktub-barbell-club/` en el build de Pages, y sigue registrado después de cargar la página.
- El stub de Flutter no lo desregistra ni lo reemplaza.
- El shell guardado incluye lo necesario para arrancar, CanvasKit incluido, sin pedirlo al CDN.
- El service worker no guarda respuestas de la API ni datos del día (eso es E7).
- `flutter analyze` y `flutter test` en `apps/frontend` siguen limpios.

## Restricciones

- CLAUDE.md › Offline: service worker propio para el shell, con scope en el base path de Pages. Los datos del día los guarda la app, fuera de este issue.
- design.md §3.4 ("Sin señal"): el service worker propio reemplaza al de Flutter 3.47.
- design.md §4.2 y E0 › Contingencia: si el service worker propio no funciona en la PWA instalada, se frena y se rediseña con el usuario antes de seguir con 7.5.
- CLAUDE.md › Qué es: el código nuevo va en inglés (identificadores y comentarios del service worker incluidos).

## Decisiones cerradas

- Service worker propio, no el de Flutter (CLAUDE.md › Offline; design.md §3.4).
- Scope en el base path `/maktub-barbell-club/` (CLAUDE.md › Offline).
