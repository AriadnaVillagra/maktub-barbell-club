# E1.13 — App: pantalla de ingreso con Google

## Cambio

Agregar la pantalla de ingreso con el botón que dibuja la librería de Google, mandar el ID token al backend apenas llega, mostrar el rechazo de un email desconocido y redirigir según haya o no sesión.

## Dónde cae

- `apps/frontend/lib/app/router.dart`: hoy no hay ruta de login. Hay que agregarla y redirigir cuando no hay sesión.
- `apps/frontend/lib/features/<feature de sesión>/presentation/`: pantalla y provider (el feature de E1.12).
- `packages/maktub_ui`: tokens y componentes para toda la pantalla.
- El client ID entra por `--dart-define`, igual que `API_URL` (CLAUDE.md › Commands).

## Debe ser cierto después

- Se muestra el botón de Google; al elegir cuenta, el ID token llega al endpoint de E1.7.
- Un email desconocido muestra un mensaje claro en pantalla y no dispara renovación (test).
- Con sesión, la app abre el shell; sin sesión, abre el ingreso.
- Funciona desde `http://localhost` con el client ID real.
- Desde `https://ariadnavillagra.github.io`, la prueba corre al mergear E1 a `main` (design.md §2 D2), con la PWA publicada por E0.1.

## Restricciones

- design.md §3.4 y F1 §5: el botón es el que dibuja Google. `google_sign_in` no sirve para el código de autorización en web.
- CLAUDE.md › `maktub_ui`: las pantallas no usan colores, tamaños, espaciados ni estilos de texto literales. Si falta un componente, va al paquete con su sección de galería.
- CLAUDE.md › Frontend: clean architecture por feature, sin lógica de dominio en presentación.
- Código nuevo en inglés (CLAUDE.md, intro).

## Decisiones cerradas

- Botón de Google dibujado por la librería, con el ID token enviado al backend al llegar (design.md §3.4).

## Bloqueos externos

- El client ID real (E1.1).
