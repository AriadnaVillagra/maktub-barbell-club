# E7.11 — Temporizadores en la sesión

## Cambio

Se conectan los temporizadores a la sesión, reutilizando el temporizador que ya existe en el repo
(`Crono`, `CronoController`, `BarraCrono`, `elegirTemporizador`):

- Al marcar una serie arranca el temporizador de su prescripción.
- Selector manual de temporizador.
- Countdown, EMOM y tabata, como en la referencia, con sonido, vibración y pantalla encendida.
- Si el dispositivo no permite sonido, vibración o pantalla encendida, nada falla.

## Dónde cae

- `apps/frontend/lib/features/temporizador/` (existente) y `apps/frontend/lib/features/sesion/presentation/`
  para engancharlo a marcar una serie.

## Debe ser cierto después

- Marcar una serie arranca el temporizador de su prescripción (test).
- Countdown, EMOM y tabata se comportan como en la referencia (tests con el modelo de E2.2).
- Con sonido, vibración o pantalla encendida no disponibles, el temporizador sigue corriendo sin error
  (test con plataforma falsa).
- `crono_test.dart` sigue verde.
- La prueba de sonido, vibración y pantalla encendida en la PWA instalada se hace después del merge
  de E7 (D3).
- `flutter test` y `flutter analyze` quedan limpios.

## Restricciones

- No reescribir `Crono`: es la base de F8 (CLAUDE.md, "features/temporizador").
- Los temporizadores son datos (E2.2). Este issue no define el modelo.
- Código nuevo en inglés (CLAUDE.md).
