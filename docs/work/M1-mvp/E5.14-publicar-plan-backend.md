# E5.14 — Modelo y backend: publicar un plan

## Cambio

Un plan guarda aparte la última versión publicada, y un endpoint nuevo la publica si el plan está completo.

## Dónde cae

- `packages/maktub_core/lib/src/modelos/plan.dart`: copia publicada dentro de `Plan`.
- `apps/backend/lib/features/plan/publicar/`: slice nuevo, y `routes/clubes/[clubId]/planes/[planId]/publicar/`.
- `apps/backend/lib/features/plan/guardar/` y `listar/`.

## Debe ser cierto después

- `Plan` tiene una versión publicada opcional: modelos de semana, asignación semanal, fecha y autor. Un plan guardado sin ella se sigue leyendo.
- `POST .../planes/{planId}/publicar` copia lo guardado a la versión publicada, en una sola escritura. Solo el coach (`Accion.planificar`).
- Un plan con cualquier problema de `validatePlan` no se publica: responde 422 con `problemas`, igual que guardar, y la versión publicada anterior queda intacta.
- Guardar (`PUT`) nunca modifica la versión publicada: lo que venga en el cuerpo se ignora.
- El listado de planes indica si el plan está publicado.
- Tests con stores falsos y `testClubIsolation`; `dart analyze`, `dart test` y `dart_frog build` pasan.

## Decisiones cerradas

- Decidido por Ari el 2026-11-08: guardar siempre deja un borrador que ve el coach; los atletas ven solo lo publicado.
- Si un plan publicado se edita, los atletas siguen viendo la última versión publicada hasta que se vuelva a publicar.
- Publicar es una sola escritura de documento (D15).
