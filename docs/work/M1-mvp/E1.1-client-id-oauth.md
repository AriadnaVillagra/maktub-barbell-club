# E1.1 — Client ID de OAuth en GCP (manual)

## Cambio

El usuario crea el client ID de Google con los orígenes `https://ariadnavillagra.github.io` (sin ruta) y `http://localhost`, y deja la pantalla de consentimiento en modo prueba con Andi y Ari. Es una acción manual del usuario, sin código.

## Dónde cae

- Consola de GCP, proyecto `maktub-514012` (CLAUDE.md › Commands).
- design.md §3.6 (client ID y consentimiento).
- El valor resultante no va al repo como secreto: entra por configuración en E1.6 (backend) y E1.13 (app).

## Debe ser cierto después

- Existe un client ID con los dos orígenes cargados.
- Con ese client ID, el botón de Google responde desde `http://localhost`.
- La pantalla de consentimiento está en modo prueba con los dos usuarios.
- Mientras se construye, R2 se prueba con `http://localhost`. La prueba sobre `https://ariadnavillagra.github.io` queda para cuando se mergea E1 a `main` (design.md §2 D2).

## Restricciones

- Contingencia de design.md §4.2 (M1 R2): si Google no acepta el origen de GitHub Pages, cambia la forma del ingreso (dominio propio u otro hosting). La prueba sobre `github.io` al mergear E1 es el punto donde eso se confirma.

## Decisiones cerradas

- Orígenes del client: `https://ariadnavillagra.github.io` (sin ruta) y `http://localhost` (design.md §3.6).
- Pantalla de consentimiento en modo prueba con los dos usuarios (design.md §3.6).

## Bloqueos externos

- Acción manual: la hace el usuario en la consola de GCP.
